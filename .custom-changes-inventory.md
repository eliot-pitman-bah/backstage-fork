## Problem Statement

**Current Challenge:** Manual cherry-picking of 7 commits when upgrading is:

- ❌ Error-prone (easy to miss files)
- ❌ Not scalable (doesn't scale to future upgrades)
- ❌ Undocumented (hard to remember what changed)
- ❌ Labor-intensive (requires manual diff review for each version bump)

**Goal:** Upgrade v1.44.2 → v1.49.2 → future versions while preserving **4 types of changes**

1. New features (FormContext)
2. UI enhancements (TaskSteps accordion)
3. Namespace curation (@bip-bih rebranding)
4. Publishing config (Nexus registry)

## Proposed AI-Driven Solutions

### Strategy 1: **Git Patch Files + LLM Validation** (RECOMMENDED)

**Approach:** Store custom changes as .patch files with AI-generated documentation

- ✅ **Pros:** Works with any Backstage version, zero runtime dependencies, git-native
- ✅ **Pros:** LLM can validate patch applicability on new versions
- ⚠️ **Cons:** Manual patch generation needs one-time setup

**Implementation:**

```bash
# Generate patches for each logical change group
git format-patch v1.44.2..1.44.2 -o patches/

# Creates:
# - patches/0001-TaskSteps-accordion-wrapper.patch
# - patches/0002-FormContextProvider-new-feature.patch
# - patches/0003-BIP-BIH-namespace-rebranding.patch
# - patches/0004-Nexus-publishing-config.patch
```

**LLM Agent Role:** For each upstream version bump:

1. Read the stored patches
2. Analyze upstream changes in that version
3. Flag conflicts: "This patch affects line range X, but upstream changed Y in that range"
4. Auto-resolve easy conflicts (whitespace, import order)
5. Generate conflict report for review

---

### Strategy 2: **Custom Plugin Wrapper Pattern** (SCALABLE)

**Approach:** Keep @backstage plugins unmodified, layer custom features via composition/plugins

- ✅ **Pros:** Upstream stays clean, custom code is isolated
- ✅ **Pros:** Easier to upgrade (zero conflicts possible)
- ⚠️ **Cons:** Requires rearchitecting FormContext/TaskSteps into separate plugins

**Implementation:**

```
plugins/
  scaffolder-react/           # Keep pristine @backstage version
  scaffolder-react-bip-bih/   # Custom layer
    - FormContextProvider.tsx
    - TaskStepsWrapper.tsx
    - useCustomScaffolderFeatures.ts
```

**LLM Agent Role:** Generate wrapper components and composition HOCs that enhance unmodified base plugins

---

### Strategy 3: **Semantic Change Tracking + MCP Server** (ADVANCED)

**Approach:** Use MCP server that understands semantic vs. syntactic changes

- ✅ **Pros:** Intelligent conflict detection (understands code meaning)
- ✅ **Pros:** Can propose fixes, not just report conflicts
- ⚠️ **Cons:** Requires custom MCP server development

**Components:**

- **MCP Server:** Analyzes code structure, identifies what each change does
- **Agent Task:** For each version upgrade, query: "What did we change and why?"
- **Validation:** Verify those same concepts still apply in new version

**LLM Agent Role:** Run semantic analysis on patches, suggest rewrites for breaking changes

---

### Strategy 4: **Git Worktree + Automated Rebase** (PRACTICAL)

**Approach:** Maintain `custom/main` branch as permanent "diff" against upstream

- ✅ **Pros:** Single source of truth for all customizations
- ✅ **Pros:** Git handles most of the mechanical work
- ⚠️ **Cons:** Requires discipline (all changes go on custom/\* branches)

**Implementation:**

```bash
# Upgrade workflow
git checkout master && git pull upstream/v1.49.2
git checkout custom/v1.49.2
git rebase master  # Auto-resolve what can be resolved
# LLM agent reports conflicts + suggests fixes
```

**LLM Agent Role:** Analyze rebase conflicts, suggest resolution with git commands

---

### Strategy 5: **Change Documentation + Automated Application** (HYBRID)

**Approach:** Document WHAT changed and WHY, then use LLM to reapply conceptually

- ✅ **Pros:** Humans understand motivation, AI handles mechanical work
- ✅ **Pros:** Creates institutional knowledge

**Implementation:**
Create `.custom-changes/` directory with structured metadata:

```json
{
  "changes": [
    {
      "id": "tasksteps-accordion",
      "description": "Wrap MuiStepper in Accordion component for collapsible steps",
      "files": [
        "plugins/scaffolder-react/src/next/components/TaskSteps/TaskSteps.tsx"
      ],
      "type": "ui-enhancement",
      "criticalityIfDropped": "medium",
      "upstreamCompatibility": "high"
    },
    {
      "id": "form-context",
      "description": "Add FormContextProvider for cross-component form state management",
      "files": ["plugins/scaffolder-react/src/formContext/FormContext.tsx"],
      "type": "new-feature",
      "criticalityIfDropped": "critical",
      "upstreamCompatibility": "high"
    }
  ]
}
```

**LLM Agent Role:**

- When upgrading, read this metadata
- Re-generate each change in the new version with updated syntax/APIs
- Create changeset files automatically
